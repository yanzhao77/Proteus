# 产品规格（Product Spec）— p-001 Todo SaaS

> 依据 requirements.md（FR-1~FR-5、A1~A4）与 user-stories.yaml（US-001~US-004）整理；不新增需求。

## 1. 产品定位与目标用户

**一句话定位**：轻量级个人待办管理 SaaS——注册即用，网页端快速记录、勾选、删除自己的待办事项。

**目标用户画像（简述）**：
- 个人效率用户：需要随手记录任务清单、用最简单方式追踪"做完没做完"的个体（核心人群）。
- 轻量团队场景的个人使用者：在团队协作功能缺失的前提下，仅作为个人任务管理工具使用（A4 界定）。
- 技术验证视角：本项目同时作为 Phase 2 最小闭环的落地样板，供后续 Phase 7（PostgreSQL + Docker）演进。

## 2. 用户旅程（核心流程，含状态）

状态说明：`未认证` → `已认证` → `待办已就绪`，全程数据按 user_id 隔离（A3）。

```
[访客] ──注册──▶ [未认证] ──注册成功(自动登录)──▶ [已认证]
                                    │
[已有账号用户] ──登录──▶ [已认证] ◀──失败(401)── 错误凭据
                                    │
                    [已认证] ──进入待办列表──▶ [待办已就绪]
                                    │
      ┌─────────────────────────────┼──────────────────────────────┐
      ▼                             ▼                              ▼
 创建待办                       勾选/取消完成                   删除待办
 (201 返回 todo)             (PATCH done 生效)               (204 移除)
      └──────────┬────────────────┴──────────────────────────────┘
                 ▼
          列表实时反映变更（仅本人数据，created_at 升序）
```

旅程步骤（含状态）：
1. **注册**：访客提供邮箱 + 密码（≥8 字符，弱密码拒绝）→ 注册成功即自动登录，返回 JWT token（US-001；FR-1）；邮箱已注册返回 409。
2. **登录**：已注册用户凭邮箱 + 密码登录 → 正确凭据返回 token（US-002；FR-2）；错误凭据返回 401，不区分具体原因。
3. **创建待办**：已认证用户在待办页输入 title（1–200 字符）→ 创建成功返回 201 与 todo 对象（US-003；FR-3）。
4. **查看/完成待办**：列表仅返回本人 todo；勾选切换 done 状态并持久化（US-003；FR-3）。
5. **删除待办**：删除确认后返回 204，列表移除该项（US-003；FR-3）。

## 3. 功能清单

| Feature | 描述 | 验收标准（对应 user stories） | 优先级 |
|---|---|---|---|
| 用户注册 | 邮箱 + 密码注册，密码 bcrypt 哈希存储 | 邮箱+密码可注册；弱密码（<8 字符）拒绝；注册后自动登录并返回 token（US-001 / FR-1） | P0 |
| 用户登录 | 邮箱 + 密码校验，签发 JWT token | 正确凭据返回 token；错误凭据返回 401（US-002 / FR-2） | P0 |
| 待办创建 | 新增待办，归属当前用户 | 创建返回 201 与 todo 对象；title 非空且 ≤200 字符（US-003 / FR-3） | P0 |
| 待办列表 | 仅返回当前用户（本人）的待办 | 列表仅返回本人 todo（按 user_id 过滤，A3）；他人资源视为不存在（404）（US-003 / FR-3） | P0 |
| 待办完成状态 | 更新 done（及 title）状态 | 更新 done 状态生效并持久化（US-003 / FR-3） | P0 |
| 待办删除 | 删除本人待办 | 删除返回 204（US-003 / FR-3） | P0 |
| 前端单页应用 | React + Vite 构建的 SPA：登录 / 注册 / 待办列表 | 网页可完成注册登录与待办的展示/添加/勾选/删除（US-004 / FR-4） | P1 |
| 健康检查端点 | GET /health 返回服务状态 | 服务启动后可访问，返回 200（FR-5） | P1 |

## 4. 页面清单（对应前端实现，FR-4 / US-004）

| 页面 | 路由 | 功能 | 对应需求 |
|---|---|---|---|
| 登录页 | /login | 邮箱 + 密码登录；成功跳转待办列表；错误展示 401 提示 | FR-2 / US-002 |
| 注册页 | /register | 邮箱 + 密码注册；成功即自动登录并跳转待办列表；弱密码/邮箱已注册提示 | FR-1 / US-001 |
| 待办列表页 | /todos（受保护） | 展示本人待办；新增输入框创建；勾选切换完成状态；删除按钮移除；未认证访问跳转登录 | FR-3 / US-003 |

页面间流转：未认证访问 /todos → 跳转登录页；登录/注册成功 → 跳转待办列表页。

## 5. 范围外（Out of Scope）

- 邮件验证（邮箱真实性校验，A4 明确不实现）
- 找回密码 / 修改密码流程
- 团队协作（多用户共享待办、权限、邀请，A4 明确不实现）
- 移动端原生 App 或响应式深度适配（仅桌面浏览器为目标）
- 待办分类 / 标签 / 提醒 / 截止日期等高级管理能力
- 以上各项 Phase 7 也保持 Out of Scope（A4）

## 6. 成功指标（本地 MVP）

本地开发环境（Phase 2）可度量项，目标基线结合 P95 < 500ms（非功能需求）：

| 指标 | 定义 / 度量方式 | 目标 |
|---|---|---|
| 注册→创建待办转化 | 完成注册（拿到 token）后 10 分钟内创建至少 1 条待办的会话占比 | ≥ 80%（本地冒烟验收） |
| 任务完成率 | 已勾选 done 的待办数 ÷ 全部待办数 | ≥ 30%（单用户演示数据） |
| 登录成功率 | 正确凭据登录返回 token 的用例占比（自动化测试） | 100%（pytest 覆盖 US-002） |
| 数据隔离正确率 | 跨用户访问他人待办均返回 404 的用例占比 | 100%（QA 边界用例） |
| 注册/登录接口正确性 | 注册 201/409、登录 401 语义符合 api-spec 的用例占比 | 100%（pytest 覆盖 US-001/002） |
| 前端核心路径可用 | 冒烟用例：注册→登录→创建→勾选→删除全流程无阻塞 | 100% 通过 |

> 说明：以上为本地 MVP 的验收型指标（以自动化/冒烟用例通过率为主）；真实用户转化类指标（注册→创建转化）待 Phase 7 部署后按埋点数据统计。
